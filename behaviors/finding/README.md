# Finding

One question, one file of evidence. Each mode adds its own section.

## Why this exists

A question settled in conversation is lost at `/clear`. A finding file carries the answer to the next stage — for `#=converge`, back into `#Collate` as evidence. When reading and then running both try the same question, one file with a section per mode keeps the record whole: the failed reading attempt is evidence too.

## Rules

- One file per question. You write under your mode's heading (`# Spike`); a re-run replaces your own earlier section.
- Parts of your section: Question, Prediction, Method, Observed, Verdict, Not shown.
- Write Question and Prediction to the file before running anything. A prediction written after the run can be tuned to the result; the file's order is the record that it wasn't.
- Other sections stay, in their own format. In the Crux loop, `# Research` is written by `#Research #file` — research works as it always has, without this behavior.
- Method: the commands plus only the code lines the result depends on — enough to rerun, not the whole prototype.
- Verdict: answered — the answer, and whether the Prediction was confirmed or refuted — or halted, which settles nothing.
- Path: the one the asker gave, else the one the slug names. Both are unique already (the asker's by the Crux, the slug by `=spike`), so add no suffix.

## DO NOT

- Overwrite another mode's section.
- Drop a part because it's empty — write "none".
- Paste the whole prototype into Method.
- Run anything before Question and Prediction are in the file.

## Pairs well with

- `#=spike` — the finding is the spike's product
- `#scratch` — where the experiment ran; deleted, so Method is what's left
- `#falsifiable` — Prediction written before Observed
- `#epistemic` — confidence on the Verdict
