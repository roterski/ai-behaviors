# #html — HTML
Present anything that needs the user's input as an html-channel page.

∀ output needing the user's decision, choice or review: an html-channel page that follows its CONVENTION. html ∩ {MarkdownOptionList, AnswerOutsideRuntime, ActingBeforeDone, QuestionWithoutNote, UnclearableAnswer, ActingOnDeferred} = ∅    -- HARD CONSTRAINT
Prefer the MCP tools: channel_setup → write the page → check_page → run `html-channel wait <session>/<page>` as a background command → give the URL lines html-channel returns in your final message → end the turn. Fix every error check_page reports and read its dark screenshot before giving the URL. Else the `html-channel` CLI, following the html-channel skill. Neither installed: say so, then fall back to markdown.
The wait's exit wakes you with its status: done → act on its decisions; deeper → its Deeper targets; superseded → nothing, the newer revision's wait covers it; waiting → wait again. Every page rewrite, also one asked for in chat, starts a new wait. Client can't wake you on a background command's exit: end the turn, get_decisions when the user says "done".
Show code changes as diffs, not before/after copies, including edits you propose before applying them; with per-hunk decisions when the user reviews changes. Markup: CONVENTION's Diffs section.
Question = each data-decision ID except status, notes, *-note, sources and hunks. After its controls: <button data-clear="ID">Clear</button>, then <textarea rows="2" data-decision="ID-note" placeholder="Another answer, or a comment"></textarea>.
Decision page: don't act on its answers until done=true. Unanswered = ID and ID-note each absent, null or "" (checkbox false is an answer) → deferred: name it in your reply, don't act on it. "moot" = another answer made the question moot: name it as moot, don't act on it; with a note: ask before acting. Note alone = the answer; choice + note = the choice qualified by the note; a note contradicting its choice: ask before acting. Deeper targets: revise the page with them expanded, start a new wait, give the URL lines again in your final message, end the turn. Report-only page: no Done button, no questions, no waiting.
sources (code-link settings, recorded on Done): for each repo with overridden=true, name it, its default and its root, and ask whether that checkout is expected and whether to switch to it, before acting on the page's answers.
hunks (diff hunks, recorded on Done): each ID.KEY answer's file and old/new lines; name a hunk by its file and lines, never by its KEY. An ID.KEY answer whose KEY isn't in hunks is about a hunk that has since changed: stale; name it by its answer and note, don't act on it.
With #zoom: a step is a page revision; its Deeper targets are <button data-deeper="target"> on the page, and the deeper list is the user's pick.
With #atlas: the page is concept-atlas's viewer, never yours to write or rewrite; follow `concept-atlas guide`, wait with `concept-atlas wait <slug>` in place of `html-channel wait`, and answer a request with a patch, not a page revision.
With #decision-ready: links between questions are page script, driven by data-state (CONVENTION's JavaScript section): change events miss buttons and Clear, and restored answers arrive asynchronously, as "saved" or "carried", not at load. On every data-state change, grey moot questions from the controls' current state, with kit tokens and opacity, not disabled, so Clear and its note still work, and blank a moot checkbox or text control: untick it, empty it. When a controlling question's data-state becomes "pending", compare its answer with the one at its previous data-state change: htmlChannel.record(ID, "moot") when it starts making ID moot, null when it stops. Moot by your links but not recorded "moot": entry absent or a carried answer → treat it as moot and say so; null (cleared) → deferred; an answer from this revision → ask before acting. A diff with hunk choices is one question: one block above it carries context, lean and links; a risky hunk gets an "if wrong" line next to the diff, naming it by file and lines.
