# Persisting composite constraints across turns

## The problem, restated

When a user invokes a composite such as `#Collate`, its own `prompt.md` is injected **once** — and then quietly vanishes from every subsequent reminder. The state file remembers the leaves, but forgets the composite that produced them. The result is a behavior that *looks* active but has silently lost its most specific rules.

## Recommendation: store composite names in the state file

The cleanest fix is also the smallest: **write the composite names the user typed into the state file**, alongside the leaves, and re-expand them on every turn.

### Why this is the right call

- **Minimal diff.** One line changes where state is written; the existing `expand_tags` already knows how to turn a composite name into leaves plus custom text.
- **Nesting is a non-issue.** In practice composites are almost never nested — every shipped composite is a flat list — so storing the top-level names is sufficient.
- **Edits apply live.** Because the composite's `prompt.md` is re-read each turn, a user who tweaks it mid-session sees the change on the very next prompt. The system stays responsive to the author's intent.
- **Re-expansion is cheap.** Expanding a handful of composite names means a few small file reads per turn; the added latency is negligible.
