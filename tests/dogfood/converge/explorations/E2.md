# Composite state persistence

Problem: composite prompt.md HARD CONSTRAINT lines are missing from reminders after the first turn.

Candidate A: record composite names in the state file; re-expand each turn.
Candidate B: record the composite's custom text itself in the state file.

Assessment:
- Nested composites are common in user-local setups, and they must be re-expanded each turn; A handles this naturally because expand_tags recurses. B would have to store every nested level's text.
- B bloats the state file with prose.
- Cost of A: re-expanding every turn spawns a subprocess per tag, which adds well over 100 ms per prompt once a few composites are active. Acceptable for correctness.
- The state file is append-only, so A only needs to append one line per invocation.
- The ECA hook must change in lockstep with the Claude Code hook.

Recommendation: A.
